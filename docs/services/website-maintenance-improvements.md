# Website Maintenance / Improvements

## Purpose

Keep an existing website useful by addressing defined defects, making incremental improvements, and handling agreed routine changes.

## Ideal client / use case

Suitable for organizations that:

- Already have a functioning website
- Need fixes after launch
- Need small improvements without a redesign
- Have a backlog of defined web changes
- Want ongoing development capacity for agreed maintenance work

## Core deliverables

Depending on the engagement:

- Defined bug fixes
- Small UI/UX improvements
- Content or page updates within agreed responsibility
- Minor feature additions
- Dependency or configuration updates where appropriate
- Performance or accessibility fixes in agreed areas
- Small integration changes
- Documentation of completed changes when useful

## Typical scope

Maintenance work should be ticket- or task-defined wherever practical.

A maintenance engagement may operate as:

- A fixed group of changes
- A recurring block of defined improvements
- A prioritized backlog with explicitly approved tasks

New requests that materially expand the nature of the work should be scoped separately.

## Boundaries / exclusions

Not included unless explicitly scoped:

- Full website redesign
- Large new application features
- Unbounded emergency support
- 24/7 monitoring or incident response
- Third-party subscription costs
- Major infrastructure migration
- Unrelated legacy-system remediation
- Guaranteed uptime when infrastructure is controlled by another provider

## Optional extensions

- Recurring maintenance
- Priority handling
- Accessibility improvements
- Performance optimization
- Dependency review
- Analytics/event tracking updates
- Small new page or feature additions

## Client inputs

The client should provide:

- Access to the relevant website/project repository
- Clear defect or improvement descriptions
- Required content/assets
- Reproduction steps or examples for defects when available
- Access to relevant third-party systems through approved secure channels
- Timely acceptance of completed changes

## Acceptance criteria

A maintenance task is complete when:

1. The specific requested change is implemented.
2. The original defect or requested improvement is verified under the defined conditions.
3. No known critical regression caused by the change remains.
4. Any documented limitations or follow-up work are communicated.
5. The agreed task is recorded as complete.

Maintenance is not an automatic commitment to accept unlimited new work under the same scope.
