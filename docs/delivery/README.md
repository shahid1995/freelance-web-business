# Delivery

Client delivery guidance, project lifecycle, discovery, scope, milestones, QA, handover, and closure practices belong here.

Individual client project implementation remains in the client's separate repository.

## Phase 3 components

- client-discovery.md — discovery process, questions, outputs, boundaries, and handoff to scope
- project-scope.md — scope baseline, deliverables, acceptance, exclusions, responsibilities, dependencies, and change control
- project-milestones.md — sequencing, readiness, dependencies, completion criteria, blockers, review, and handoff
- quality-assurance.md — verification coverage, defect handling, QA gates, evidence, exceptions, and handoff to handover
- project-handover.md — transfer package, operational ownership, access, acceptance, corrections, and closure readiness
- project-closure.md — final reconciliation, acceptance/handover closure, access cleanup, administrative completion, evidence, and post-closure routing

## Delivery lifecycle

Accepted opportunity → Delivery handoff → Discovery → Scope → Milestones → Implementation and QA → Handover → Project closure

The future customer application will provide the operational interface for live customer/project delivery records while preserving these reusable business rules.

Discovery, scope, milestones, QA, handover, and closure must not silently expand the accepted commercial agreement. Material changes require the agreed change-control process.

Client-specific source code remains in the client's separate repository. Live client/project records must use a secure client/project operating location or the future customer application as approved; they do not belong in this public repository.
