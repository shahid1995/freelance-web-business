# Portfolio Index

This file is the registry of portfolio items. It records what exists, what may be published, and what evidence supports each item.

## Publication rules

A portfolio item must not be presented as client work unless it is genuinely client work.

Use these ownership/status categories:

- Client — real client project
- Founder-owned — work owned and created by the Founder/business
- Demonstration — intentionally created to demonstrate capability
- Concept — design or implementation concept that is not represented as delivered client work

Publication status:

- Draft
- Candidate
- Approved
- Published
- Restricted
- Archived

## Portfolio item requirements

Before an item becomes a public case study, the repository should contain:

- A completed project record with its canonical Project ID
- Accurate ownership and role
- Defined scope
- Evidence supporting major claims
- Approved screenshots where applicable
- Permission confirmation where client material is involved
- A case study reviewed for confidentiality and factual accuracy

## Evidence hierarchy

Prefer evidence in this order:

1. Actual implemented work
2. Approved screenshots or public links
3. Verified project measurements
4. Client feedback with permission
5. Descriptive claims that can be supported by the project record

Do not use unsupported superlatives or guaranteed business outcomes.

## Case-study readiness

A project is case-study ready when its facts, scope, role, evidence, and publication permissions have been reviewed.

A project may remain in the internal portfolio system without being published publicly.
