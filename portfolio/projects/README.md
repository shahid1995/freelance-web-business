# Portfolio Project Records

Each real portfolio project should have its own Markdown record under this directory.

## Recommended structure

Use one directory per project when a project has multiple screenshots or a case study:

portfolio/projects/project-name/

Recommended contents:

- project.md — canonical project record based on portfolio/project-template.md
- notes.md — optional internal notes appropriate for the public repository
- links.md — optional links and evidence references

Use lowercase kebab-case for project directory names.

## Project record requirements

Every project record should identify:

- ownership/status
- service category
- actual role
- problem
- agreed scope
- implementation summary
- evidence
- verified outcomes
- publication status

Do not create a project record merely to make the portfolio look larger. A record should correspond to real work, an intentionally created demonstration, or a clearly labeled concept.

## Client projects

Client-specific implementation remains in the client's project repository.

This repository may contain only the portfolio-safe record and sanitized evidence needed to represent the work.

Never copy client credentials, private customer data, confidential source code, or restricted material into this repository.

## Publication states

Use the states defined by portfolio/portfolio-index.md:

Draft → Candidate → Approved → Published / Restricted / Archived
